# Чат в редакторе темы

В редакторе библиотечной темы есть тот же боковой чат, что и в презентации: OpenAI-совместимый API или ACP, изображения и файлы, диктовка, время работы и свёрнутый журнал действий. Настройки провайдера общие, разговоры раздельные. Кнопка чата в верхнем меню скрывает панель; на узком экране она открывает её поверх холста.

Перед отправкой сообщения правки холста сохраняются. Для встроенной темы сначала создаётся собственная копия и открывается её адрес. Агент работает с этой копией; готовая тема и уже созданные презентации не меняются. Загрузка вложения во встроенную тему также создаёт копию.

Агент читает HTML/CSS через `read_theme`, меняет их через `update_theme` с проверкой версии и проверяет результат через `render_theme`. Рендер возвращает настоящее изображение шаблона 1280×720, геометрию блоков и предупреждения. Переменные вроде `{{author}}` остаются в исходном HTML; в предпросмотре они подставляются. `read_attachment` читает приложенные файлы, `use_attachment_image` переносит изображение в собственные ресурсы темы. Каталоги элементов, композиций и skills доступны для чтения.

Можно приложить PPTX/PDF/ODP и попросить перенести оформление. Агент получает первую страницу, сравнивает другие через `render_document_page`, для PPTX читает реальные master/layout/slide, шрифты, цвета и геометрию через `inspect_presentation_reference`. Нужные растровые изображения копируются через `use_reference_image` в собственные ресурсы темы. Общие линии, фигуры и текст остаются HTML/SVG с ID; пример заголовка и дата из образца заменяются переменными или исключаются. Skill `use-presentation-reference` задаёт этот порядок и финальную проверку через `render_theme`. Это создание HTML-оформления по образцу; ограничения конвертера и точности описаны [отдельно](reference-import.md).

Изменения появляются на холсте после сохранения агентом. Если во время ответа пользователь продолжил ручную правку, открытый черновик сохраняется на экране и появляется уведомление о версии агента. Черновик можно сохранить отдельной копией; обновление страницы загружает сохранённую версию. Сохранение и создание копии временно выключены во время ответа, чтобы не менять контекст разговора. Остановка запроса доступна в чате.

## Граница контекста

`/api/themes/:id/chat` использует тот же SSE-контракт, что и чат презентации: accepted, text, activity, tool, status, done, error. Редактор показывает окончательный ответ после завершения, а ход работы держит в закрытом `details`. `/chat/cancel`, вложения и предпросмотр привязаны к выбранной теме.

MCP-процесс с `--theme <id>` публикует только инструменты выбранной темы. Контекст проверяется и в bridge: прочитать другой ID, изменить презентацию, создать или удалить другую тему этими инструментами нельзя. Нативные инструменты файловой системы и терминала остаются отключёнными; неизвестные запросы разрешений отклоняются без окна подтверждения. См. [границы адаптера](agent-boundary.md).

Данные находятся вне Git в `PROJECTS_DATA_DIR/ai/`:

- `chats/themes/<id>.json` — сообщения и журнал действий;
- `attachments/themes/<id>/` — файлы чата;
- `workspaces/themes/<id>/` — изолированная рабочая папка ACP.

HTML/CSS и ресурсы самой темы остаются в `PROJECTS_DATA_DIR/themes/`. Проверки `theme-ai.test.js` охватывают scope, версии, историю и вложения. `theme-chat-ui.js` проверяет реальный HTTP/SSE-поток с mock-провайдером, копирование встроенной темы, изображение предпросмотра, обновление холста, сохранение черновика, завершение диктовки и защиту контекста во время ответа. Это не заменяет отдельную проверку авторизованного ACP-провайдера.
