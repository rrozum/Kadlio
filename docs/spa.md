# Навигация и жизненный цикл интерфейса

`frontend/app.js` — точка входа SPA. Она перехватывает внутренние ссылки, использует History API и открывает известный экран без перезагрузки документа. Прямые URL и обновление страницы обслуживаются прежними HTTP-маршрутами. Публичный просмотрщик остаётся отдельным документом; импортированный HTML не выбирает исполняемый модуль.

Каждый экран экспортирует `async mount(scope)`. Роутер получает HTML-шаблон экрана, загружает CSS в исходном порядке и вызывает mount. Шаблоны не содержат данных аккаунта или презентации: актуальные данные читает API. Шапка библиотек сохраняет DOM между разделами, поэтому меню и кнопки не смещаются.

## Ресурсы экрана

`frontend/modules/page-lifecycle.js` содержит `PageScope`. Его `document` привязывает поиск контролов к конкретному body. Поэтому отложенный обработчик старого экрана не должен искать новые поля с теми же ID. Контроллеры редактора сохраняют этот lookup при создании.

Глобальные подписки регистрируются через `listen`, таймеры — через `pageTimeout`/`pageInterval`, observers — через `PageResizeObserver`/`PageIntersectionObserver`. Дополнительное освобождение регистрируется через `onPageCleanup`. При уходе роутер завершает уже начатые API-записи, отменяет чтения и освобождает экран: закрывает SSE, отменяет streaming и диктовку, отключает observers, удаляет глобальные подписки и таймеры. Отдельные DOM-обработчики удаляются вместе с body.

```js
import { listen, onPageCleanup } from './modules/page-lifecycle.js';

export async function mount(scope) {
  const button = scope.document.getElementById('my-button');
  button.addEventListener('click', () => { /* действие экрана */ });
  listen(window, 'resize', () => { /* пересчитать расположение */ });
  const stream = new EventSource('/api/my-events');
  onPageCleanup(() => stream.close());
}
```

Не заменяйте нативные прототипы браузера и не исполняйте script из полученного HTML. Новый экран добавляется в явный список `screens` и получает `<script type="module" src="/app.js"></script>`.

## Выход и оформление

Программные переходы проходят через `navigate` из `frontend/modules/navigation.js`. Обычные внутренние ссылки перехватываются автоматически; download, внешние URL, новые вкладки и модификаторы мыши сохраняют обычное поведение. Несохранённые изменения используют существующие beforeunload guards: при внутреннем переходе роутер проверяет их и просит подтвердить уход. Редактор темы и тур также сохраняют собственные диалоги выхода.

Акценты приложения задаются `--ui-accent` и связанными переменными в `brand.css`: фиолетовый для светлой темы и зелёный для тёмной. SVG-знак наследует currentColor. Палитра слайдов остаётся внутри их документов. Переключение UI-темы использует View Transitions с учётом prefers-reduced-motion; при отсутствии API тема меняется обычным способом.

`test/spa-navigation-ui.js` проверяет общий документ и шапку, историю переходов, повторное открытие редактора и цвет акцента. Остальные browser scenarios проверяют работу экранов, хранения и экспорта.

### Плавность переходов

CSS следующего экрана загружается с `media="not all"` и активируется вместе с заменой DOM. До этого прежний экран сохраняет своё оформление. Общие шапка и футер каталогов сохраняют DOM между разделами. Смена страницы анимирует прозрачность живого содержимого за 180 мс, сохраняя шапку и футер. Снимки всего документа для навигации не используются: они накладывают старые модальные окна на новый холст и могут блокировать взаимодействие с iframe. View Transition применяется только к переключению цветовой темы и завершается при навигации. При настройке reduced motion смена происходит без анимации.

### Загрузка и отмена

Экран и его данные имеют разные жизненные циклы. Транзакция маршрута заканчивается после замены DOM и включения CSS; загрузка данных может продолжаться. Следующая навигация отменяет GET/HEAD через AbortController прежнего PageScope. Уже начатые записи заканчиваются перед dispose: заметки и CAS нельзя терять из-за ухода. Номер транзакции защищает новый маршрут от позднего завершения предыдущего. Шапка каталога доступна даже во время первоначальной загрузки; PageScope.ready освобождает редактор после готовности холста, независимо от истории чата.

Одинаковые упорядоченные наборы CSS сохраняют существующие links. При смене набора новые стили сначала загружаются неактивными. Стили функций объявлены в шаблонах экранов; import модуля не вставляет CSS в глобальный document. Это важно при повторном использовании ES-модулей из кэша браузера.

Карточки проектов, выбор темы и миниатюры ленты обслуживает общий preview-frame: loading → ready/error. Документ iframe скрыт до загрузки CSS, шрифтов и декодирования изображений; масштаб устанавливается до раскрытия. Заглушка наследует палитру приложения, а слайд сохраняет собственную палитру. Освобождение экрана отключает listeners и observers превью.

Чат первоначально показывает loader, а не подсказки и предложение подключения. Подсказки появляются только после подтверждения пустой истории и получения настроек провайдера. Загрузка истории не блокирует готовый холст. Ошибка загрузки имеет отдельное сообщение.

Дополнительный test/spa-loading-ui.js искусственно задерживает CSS и историю, проверяет скрытые незавершённые превью, готовность чата, уход с незавершённого экрана и сохранение общих stylesheet nodes.
