# Подключение ИИ-провайдера

ИИ-модуль находится в `backend/modules/ai/`. Сервис отвечает за контекст, историю, активные ходы, отмену и события; транспорт провайдера — за связь с моделью. MCP/инструменты находятся отдельно в `backend/modules/mcp/` и работают с движком.

## Существующие варианты

`providers/registry.js` явно подключает `openai` и `acp`. OpenAI-совместимый endpoint выбирается существующими настройками, поэтому другому совместимому сервису не нужен отдельный провайдер. Несовместимый протокол добавляется адаптером.

Реестр `ProviderRegistry` принимает объекты:

```js
{
  id: 'example-api',
  validate(settings) { /* Проверка полей настройки. */ },
  async preflight(settings) { /* Готовность перед началом работы. */ },
  async run(turn) { /* Запрос, инструменты, отмена, события. */ },
}
```

Все три метода обязательны, ID допускает строчные латинские буквы, цифры и дефис. Повторный ID отклоняется.

Для адаптера с долгоживущими процессами доступны необязательные `reset(contextKey)` и `close()`. Реестр вызывает их у всех подключённых адаптеров при сбросе контекста и остановке приложения: контекст мог раньше использовать другого провайдера. Собственный ACPManager должен передавать эти вызовы в `manager.reset(key)` и `manager.close()`, чтобы не оставлять дочерние процессы.

## Минимальный адаптер API

Пример подключения транспорта, уже реализующего обработку запроса и инструментов:

```js
// backend/modules/ai/providers/example-api.js
export function createExampleProvider({transport}) {
  return {
    id: 'example-api',
    validate(settings) {
      if (!settings.apiKey || !settings.model) {
        throw Object.assign(new Error('Укажите ключ и модель.'), {status: 409});
      }
    },
    preflight(settings) {
      this.validate(settings);
    },
    run(turn) {
      return transport({
        settings: turn.settings,
        messages: turn.recent,
        projectId: turn.themeId ? undefined : turn.id,
        themeId: turn.themeId,
        tools: turn.tools,
        signal: turn.signal,
        onEvent: turn.onEvent,
      });
    },
  };
}
```

В существующей фабрике `createProviderRegistry({acp})` подключите адаптер через `registry.register(createExampleProvider({transport}))`. Транспорт нужно реализовать под протокол поставщика; пример не подменяет tool calling простой строкой ответа.

Новый ID не появляется в интерфейсе автоматически. Изменение списка провайдеров и формы настроек — отдельная доработка frontend. Текущий рефакторинг сохраняет два прежних варианта.

## Контракт хода

`run(turn)` получает `settings`, `id`, `scope`, `key`, `themeId`, `recent`, `selected`, `chat`, `attachmentContext`, `projectContext`, `tools`, `signal`, `onEvent` и callbacks `onSession`/`clientFactory`.

- `tools.execute(name, args, context)` — единственный путь изменения. Перед записью нужно прочитать актуальный объект и его версию.
- `signal` нужно передавать в сеть и длительные операции. Отменённый ход не должен продолжать скрыто писать данные.
- Итоговый текст передаётся событием `{type: 'text', text}`. `activity`, `tool` и `status` идут отдельно и показываются в свёрнутом журнале.
- Нельзя пересылать скрытые рассуждения, stderr, ключи или токены в чат.
- Историю сохраняет сервис. Адаптер не пишет второй файл истории и не удаляет старые сообщения.
- Изображения должны уходить в модель как image content, а не как текстовый base64 без поддержки vision.

Проверьте адаптер mock-обменом: обычный ответ, инструмент с конфликтом версии, image content, ошибка endpoint и отмена. Реальная авторизация/инференс проверяются отдельно.

## Другой ACP-агент

Оператор может задать `ACP_COMMAND` — путь к исполняемому адаптеру — и `ACP_ARGS_JSON` — JSON-массив аргументов. Браузер не выбирает executable, cwd или аргументы.

`ACPManager` выполняет handshake и передаёт привязанный MCP с инструментами текущего проекта либо темы. Встроенный Codex имеет дополнительную фиксированную политику отключённых нативных возможностей. Для другого ACP executable нельзя обещать такую же ОС-изоляцию без проверки его поведения.

Сохраняйте точное сопоставление исходного tool call с зарегистрированным именем. Native/unknown permission requests отклоняются автоматически и не создают запрос к владельцу. Не добавляйте чтение файлов или terminal capabilities для удобства адаптера: HTML доступен через MCP.
