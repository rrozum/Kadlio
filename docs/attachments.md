# Вложения в чате

У сообщения могут быть изображения и файлы с исходными материалами. Вложения принадлежат презентации, хранятся в `PROJECTS_DATA_DIR/ai/attachments/<projectId>/` и доступны через защищённый API. В Git, публичную ссылку на презентацию и JSON истории чата содержимое файлов не попадает. История хранит ID, имя, MIME, размер и время загрузки.

Изображения PNG, JPEG, WebP и GIF передаются модели как изображения. Оригинал сохраняется, а для модели создаётся копия с длинной стороной до 1 600 пикселей и размером до 1 МиБ. PNG свыше 750 КиБ преобразуется в JPEG с качеством 85; при необходимости копия дополнительно уменьшается. GIF передаётся как первый кадр. Заголовок изображения проверяется до декодирования: предел — 25 миллионов пикселей.

Responses API получает `input_image`, Chat Completions — `image_url`; формат соответствует [официальному руководству OpenAI](https://developers.openai.com/api/docs/guides/images-vision). ACP получает блок `image` с MIME и base64, когда агент объявил поддержку изображений. Если поддержки нет, чат сообщает об этом. Для OpenAI-совместимого сервера нужно выбрать модель и API, которые принимают изображения.

Текстовые файлы и код читаются как UTF-8. HTML, JavaScript и другие исходники передаются как текст; они не запускаются. Из DOCX и PPTX извлекается текст из основной части документа или слайдов в их порядке. Для DOCX доступен текст; визуальная обработка страниц Word не реализована.

Для PDF, PPTX и ODP есть изображения страниц. Первая страница прикреплённого документа автоматически передаётся модели, если рендер доступен; другие страницы агент запрашивает через `render_document_page`. PDF рендерится PDF.js, PPTX/ODP сначала преобразуются доверенным серверным конвертером LibreOffice в изолированном процессе. PPTX также можно исследовать через `inspect_presentation_reference`: шрифты, цвета, координаты, наследование master/layout и собственные изображения. См. [оформление по образцу](reference-import.md) для точных возможностей и ограничений.

Из PDF извлекается доступный текст до 100 страниц; документ с большим количеством страниц отклоняется. OCR отсутствует: скан без текстового слоя получает текстовый статус `no_text`, но его изображение может быть доступно агенту. Статус извлечения текста и `document.status` визуального рендера независимы. Повреждённые, защищённые паролем или слишком сложные документы получают `unreadable_document`; произвольные бинарные форматы — `unsupported_format`, некорректный UTF-8 — `unsupported_encoding`. Исходный файл при этом остаётся доступен для скачивания.

## Ограничения

- До четырёх разных файлов в одном сообщении.
- До 8 МиБ на файл и 20 МиБ в сумме на сообщение.
- До 100 000 символов извлечённого текста в сумме; усечение явно отмечается.
- Для DOCX/PPTX: не больше 2 048 частей архива; XML читается потоком с пределом 2 МиБ на часть.
- Имена файлов не могут содержать путь или управляющие символы. На диске используются UUID, а MIME изображения сверяется с сигнатурой.

После сохранения сообщения сервер отправляет SSE-событие `accepted` с его метаданными. До этого события интерфейс сохраняет текст и прикреплённые файлы при ошибке. Сообщение только с вложениями разрешено. Повторное чтение старого файла идёт через `read_attachment`; большие base64-строки не дублируются в последующих текстовых запросах.

## API и инструменты агента

`POST /api/projects/:projectId/attachments` принимает `{name,mime,data}`, где `data` — обычный base64 без префикса `data:`. Ответ: `{id,name,mime,size,kind,createdAt,previewUrl?}`; `kind` — `image`, `text`, `document` или `binary`.

`GET /api/projects/:projectId/attachments/:attachmentId` возвращает защищённое содержимое файла; вариант с `/file` также подходит для скачивания. `POST /api/projects/:projectId/chat` принимает `attachmentIds`. Каждый ID проверяется в пределах текущей презентации до сохранения сообщения.

Инструмент `read_attachment` возвращает метаданные, извлечённый текст и доступное изображение, включая первую страницу поддерживаемого документа. `use_attachment_image` переносит непосредственно загруженное изображение в ресурсы презентации. `use_reference_image` переносит выбранный растровый ресурс PPTX по ID из инспектора. Это отдельные операции: загрузка в чат сама слайды не меняет. `render_slide` возвращает снимок текущего слайда. Страницы и снимки поступают модели как изображения; base64 заменяется компактными метаданными в JSON результата инструмента. Те же операции с вложениями доступны в выбранном контексте темы.

Содержимое вложений — исходные данные, а не разрешение на команды или расширение доступа. Агент продолжает работать через разрешённые инструменты презентации; см. [границы агента](agent-boundary.md).

Проверки: `node --test test/attachments.test.js test/ai.test.js test/document-preview.test.js test/presentation-reference.test.js` покрывают приватное хранение, принадлежность контексту, размеры, извлечение Office/PDF, ограничения распаковки и сообщения провайдеров. Независимая визуальная проверка описана в [оформлении по образцу](reference-import.md#проверки). Эти проверки не заменяют проверку выбранной модели и конвертера в рабочем окружении.
