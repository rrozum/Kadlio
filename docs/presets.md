# Готовые блоки и темы презентации

Каталог добавляет HTML-композиции в существующий слайд. После вставки текст, позиции и оформление меняются обычным редактором или агентом. Сохранённый HTML остаётся источником: обновление каталога не пересоздаёт ранее вставленные блоки.

В редакторе откройте **Блоки**, выберите композицию и замените текст примера. Можно перемещать композицию целиком или выбрать отдельный текст внутри неё. Для изображения используйте загруженный ресурс проекта. Тема презентации находится в панели оформления и применяется явно; светлая/тёмная тема интерфейса — отдельная настройка.

## Каталог

| ID | Назначение |
| --- | --- |
| `statement` | Крупный тезис и короткое пояснение. |
| `quote` | Цитата, автор и контекст. |
| `comparison` | Два варианта по одинаковым критериям. |
| `metrics` | Три числа, подписи и источник. |
| `steps` | Три последовательных действия. |
| `timeline` | Три вехи на временной шкале. |
| `code-card` | Фрагмент кода и его пояснение. |
| `callout` | Правило или важный вывод. |
| `image-caption` | Изображение с текстом и подписью. |
| `feature-cards` | Три связанные идеи. |
| `checklist` | Три пункта для проверки. |
| `closing` | Финальная мысль или приглашение к вопросам. |

Текст по умолчанию иллюстративный. Числа `01`, `02`, `03` — заполнители, а не измерения. Замените их подтверждёнными данными и укажите источник. Каталог не загружает внешние изображения, шрифты или скрипты.

Темы `light`, `dark`, `warm`, `midnight`, `paper` задают согласованные цвета, шрифт, фон и немного простых декораций. `paper` использует системный шрифт с засечками. Тема не гарантирует одинаковый внешний вид произвольного импортированного HTML с собственными цветами и CSS; после применения проверьте такие слайды.

## Контракт ES-модуля

`shared/addons/compositions/catalog.js` импортируется в браузере и Node.js без сборки и зависимостей:

```js
import {
  blockPresets, themePresets, renderBlockPreset, getThemePreset,
} from './presentation-presets.js';

const body = renderBlockPreset('statement', {
  blockId: 'main-idea',
  values: { title: 'Короткая мысль', body: 'Понятное пояснение.' },
});
const palette = getThemePreset('light');
```

`blockPresets` — неизменяемый массив метаданных `{id,name,description,category,width,height,defaults,fields}`. Категории: `text`, `layout`, `data`, `media`. Поле имеет `{key,label,type}`; типы — `text`, `multiline` или `asset`. Значения — строки, числа преобразуются в строки. Пропущенные поля получают значения по умолчанию. HTML в значениях экранируется. Неизвестный ID, некорректный идентификатор или значение вызывают ошибку.

`renderBlockPreset` возвращает HTML-строку. Корневой элемент имеет `data-block-type="preset"`, `data-preset-id` и `data-block-id`. По умолчанию он расположен в `left:88px;top:154px`, а размеры указаны в метаданных. Если `blockId` не задан, создаётся UUID. Текстовые элементы имеют `data-block-type="text"`, `data-preset-field` и ID вида `<blockId>-<fieldName>`; пункты списка — `<blockId>-item-<number>`. Изображение — `<blockId>-image`. При повторном редактировании сохраняйте эти идентификаторы.

`image-caption.image` принимает только путь ресурса проекта вида `/api/projects/<id>/assets/<filename>`. Пустое значение рисует место для изображения без сетевого запроса. Передайте подпись `alt`, затем проверьте пропорции. Загрузка файлов и проверка доступа остаются обязанностью сервера.

`themePresets` — неизменяемый массив объектов:

```js
{
  id, name, description,
  tokens: { background, text, muted, accent, surface, border, font },
  background: { type: 'solid' /* или 'gradient' */, value },
  decorations: [
    { id, type: 'line', x, y, width, height, color, opacity },
    // type:'circle' для простого круга
  ],
}
```

`getThemePreset(id)` возвращает известную тему или вызывает `RangeError`. Координаты декораций заданы для холста 1280×720. Цвета — шестизначные hex; фоны — сплошной цвет или встроенный линейный градиент. Декорации не содержат URL, изображений, blur или filter. Хранение полного оформления проекта, его шаблонов заголовка/подвала и проверка версии выполняются сервером.

Композиции используют CSS-переменные `--pres-bg`, `--pres-text`, `--pres-muted`, `--pres-accent`, `--pres-surface`, `--pres-border`, `--pres-font`. Сервер задаёт их в области презентации. UI-токены приложения к ним не относятся. Цвета карточек и шрифт могут меняться вместе с темой; локально отредактированный стиль конкретного блока сохраняется в HTML.

## Агент и расширение

MCP-инструменты `list_presets`, `insert_preset`, `update_design` используют тот же каталог и путь сохранения, что и интерфейс. Перед вставкой или изменением оформления читайте актуальную презентацию и используйте возвращённые версии. Skill `presentation-presets` объясняет выбор композиции и проверку результата.

Для нового блока добавьте одну запись в `blockPresets` и один renderer. Выберите стабильные ID полей, экранируйте текст и используйте токены. Предпочитайте обычный HTML, текст и простые формы. Не добавляйте новый формат сцены, фреймворк или внешний ресурс ради одного блока.

После изменения проверьте блок в каждой теме: переносы, границы, читаемость, выбор полей и движение всей композиции. Для пользовательского длинного текста может понадобиться изменить размер или сократить текст. PDF печатает HTML. PPTX сохраняет обычный текст и поддерживаемые формы редактируемыми; фон и сложные декоративные эффекты могут быть изображениями. Итоговое отображение нужно проверять в PowerPoint отдельно.
