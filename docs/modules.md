# Границы модулей

Проект разделён по ответственности. Сервис остаётся одним; новые каталоги не вводят микросервисы, DI-контейнер или обязательную сборку frontend.

| Область | Путь | Что менять здесь |
| --- | --- | --- |
| Конфигурация и запуск | `backend/config.js`, `backend/main.js` | env, пути установки, создание сервиса |
| HTTP | `backend/http/` | маршруты, ответы, Origin/Host, статика |
| Презентации | `backend/engine/presentations/` | жизненный цикл, слайды, CAS, копирование |
| Темы | `backend/engine/themes/` | библиотека тем, снимки и сохранение |
| HTML и оформление | `backend/engine/html/` | рендер, дизайн, переменные, медиа |
| Хранение | `backend/storage/` | коннекторы, SQL/файловые репозитории |
| ИИ | `backend/modules/ai/` | провайдеры, история, контекст и события |
| MCP | `backend/modules/mcp/` | definitions, привязанные инструменты, transport |
| Addons | `backend/modules/addons/`, `frontend/addons/`, `shared/addons/` | каталоги, применение, панели, runtime |
| Импорт/экспорт/previews | `backend/modules/` | адаптеры форматов и изолированный рендер |
| Холст | `frontend/engine/` | выбор HTML, геометрия, слои, изменённый исходник |
| Сценарии редактора | `frontend/editor/` | сохранение, аннотации, чат, навигация |
| Общие компоненты UI | `frontend/modules/` | API-клиент, source editor, тема приложения |
| Общие алгоритмы | `shared/presentation/` | timeline, дизайн, фабрики базового HTML |

## Направление зависимостей

HTTP и интеграции вызывают движок. Движок использует репозитории и общие алгоритмы. Shared не должен зависеть от browser DOM, Node fs, базы данных или серверного ключа.

Frontend получает JSON и HTML через API. Addon работает с тем же холстом/слайдом; его UI не создаёт ещё один объект презентации или автономное сохранение. При обновлении через API он использует версии и callbacks основного редактора.

## Порядок доработки

1. Определите область: правило данных, сценарий приложения, транспорт или UI дополнения.
2. Найдите существующую операцию движка. Используйте её и для ручного действия, и для инструмента агента.
3. Расширьте адаптер/репозиторий только там, где действительно нужен новый I/O.
4. Подключите модуль явно в composition root. Не добавляйте discovery по именам файлов или содержимому пользовательской презентации.
5. Проверьте создание, изменение, сохранение/перезагрузку и соседние сценарии, которые используют тот же контракт.

## Несколько устойчивых границ

- `slide.body` — исходник слайда; общий template layer не сериализуется в него.
- `slide.script` — отдельный JS. Он не исполняется в Node или родительском DOM.
- Timeline содержит отдельные переходы между slide references; он не становится CSS-свойством слайда.
- Заметки — речь автора, аннотации — привязанные комментарии, pending feedback — отдельные гостевые записи.
- Тема приложения хранится в браузере и не меняет палитру/шрифты презентации.
- Source editor форматирует представление, но открытие/отмена не перезаписывает сохранённые байты.
- View-only viewer и автономный HTML export исключают приватную историю, материалы и аккаунт.
- Vendor-код/шрифты сохраняют исходные байты и лицензии; обновление версии — отдельная проверяемая задача.
