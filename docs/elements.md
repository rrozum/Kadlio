# Дизайнерские элементы

Элементы — небольшие части оформления, которые можно поставить в нужной точке слайда: рамку окна вокруг примера, стрелку между блоками или маркер под важным словом. Они дополняют [текстовые композиции](presets.md). После вставки сохраняется обычный HTML, который можно читать и править вручную или через агента.

Каталог открывается в правой панели. Перетащите карточку на холст: точка отпускания мыши задаёт центр элемента, координаты сохраняются в HTML. Нажатие на карточку вставляет её в обычной начальной позиции.

Кнопка «+» в конце списка открывает создание с ИИ: опишите элемент и при необходимости приложите изображение. Результат сохраняется в общем каталоге владельца и доступен в других презентациях. Ошибка агента сохраняет запрос и вложения для повторной попытки. Генерация добавляет только шаблон в каталог; вставка на слайд выполняется отдельно.

Свои элементы хранятся в `PROJECTS_DATA_DIR/elements/<id>/element.json` как один HTML-блок с встроенными стилями и SVG. Изображения копируются в `assets/` этого элемента, а при вставке — в выбранную презентацию или тему. Поэтому удаление исходной презентации не ломает каталог и уже вставленные экземпляры. Каждый экземпляр получает собственные идентификаторы HTML/SVG и редактируется независимо.

| ID | Элемент | Применение |
| --- | --- | --- |
| `browser-window` | Окно браузера | Пример интерфейса с рамкой, кнопками и адресной строкой. |
| `terminal-window` | Терминал | Команды, вывод или небольшой технический пример. |
| `mouse-cursor` | Указатель | Обратить внимание на конкретную деталь. |
| `arrow-right` | Прямая стрелка | Направление или переход. |
| `arrow-curved` | Изогнутая стрелка | Мягкий указатель на фрагмент. |
| `arrow-elbow` | Угловая стрелка | Связь между разнесёнными блоками. |
| `arrow-double` | Двусторонняя стрелка | Обмен в обе стороны. |
| `connector` | Соединительная линия | Связь с точками на концах. |
| `brace` | Фигурная скобка | Объединить несколько пунктов. |
| `bracket` | Квадратная скобка | Обозначить границу группы. |
| `marker-highlight` | Маркер | Полупрозрачная полоса для выделения. |
| `underline` | Подчёркивание | Свободный двойной штрих. |

Текст окна, терминала и стикера остаётся отдельными HTML-блоками. Адрес в рамке браузера — обычная подпись: элемент не открывает сайт и не запускает команды из терминала. Маркер и мягкую форму удобно размещать за содержимым; используйте порядок слоёв редактора. Стрелки и скобки — самостоятельные формы, которые нужно расположить между нужными объектами; автоматической привязки к другим блокам у них нет.

## Контракт модуля

`list_elements` возвращает встроенные и пользовательские карточки без тяжёлого HTML. `create_design_element` принимает `{name,description?,width,height,body}` в контексте текущей презентации или темы. Для картинки сначала используйте `use_attachment_image`; разрешены только изображения этого контекста и встроенные растровые data URI. После создания вызовите `render_design_element` — агент получает настоящий снимок элемента без изменения слайдов. Скрипты, обработчики событий, внешние URL и глобальные таблицы стилей недопустимы.

HTTP-вставка в презентацию: `POST /api/projects/:id/slides/:slideId/elements` с `{elementId,values:{x,y},version}`; версия относится к слайду. Координаты задают левый верхний угол в пределах 1280×720. В тему: `POST /api/themes/:id/elements` с версией темы. Уже вставленный HTML не зависит от последующих изменений каталога.

`shared/addons/design-elements/catalog.js` работает в браузере и Node.js без зависимостей:

```js
import { designElements, renderDesignElement } from './design-elements.js';

const html = renderDesignElement('arrow-curved', {
  blockId: 'review-arrow',
  values: { color: '#2563eb', stroke: 5 },
});
```

`designElements` — неизменяемые JSON-совместимые метаданные `{id,name,description,category,width,height,defaults,fields}`. Категории: `frames`, `arrows`, `markers`, `shapes`. Поля имеют `{key,label,type}`; числовые поля также содержат `min`, `max`, `step`. Типы — `color`, `number`, `text`, `multiline`.

`renderDesignElement(id,{values,blockId})` возвращает HTML-строку. По умолчанию положение — `left:96px;top:180px`; размеры определяет каталог. Корень имеет `data-block-type="element"`, `data-element-id` и стабильный `data-block-id`. Если идентификатор не передан, создаётся UUID. Текстовые поля имеют `data-block-type="text"`, `data-element-field` и ID `<blockId>-title` / `<blockId>-content`.

Не переданные значения получают defaults. Цвет — пустая строка или шестизначный hex, например `#2563eb`. Пустой акцент использует `--element-color`, затем `--pres-accent`. `stroke` — число от 1 до 12, `opacity` — число от 0.05 до 1. Текст — строка до 16000 символов, которая экранируется как текст. CSS, HTML, URL и SVG-path нельзя передать вместо скалярного поля. Некорректные значения вызывают ошибку.

Векторные элементы используют inline SVG с `viewBox`, размерами 100%×100% и `currentColor`. Толщина контура сохраняется при изменении размера благодаря `vector-effect="non-scaling-stroke"`. В SVG нет глобальных ID, внешних ссылок, `defs`, `use`, `foreignObject`, скриптов или обработчиков событий. Поэтому несколько экземпляров не конфликтуют между собой и не загружают ресурсы из сети.

Окно браузера подстраивается под токены презентации. Терминал сохраняет тёмный фон и светлый текст; стикер по умолчанию использует светло-жёлтый фон и тёмный текст. При заданном цвете фона стикер выбирает светлый или тёмный текст по его яркости; при пустом — использует токены презентации. После собственного изменения цвета проверьте контраст.

## API и агент

Каталог доступен через `GET /api/elements` как `{elements:[...]}`. Вставка в слайд: `POST /api/projects/:id/slides/:slideId/element` с `{elementId,values?,version}`. Сервер сохраняет HTML через обычный путь изменения слайда с проверкой версии.

Агент использует `list_elements` и `insert_element`; skill `design-elements` описывает этот сценарий. Сначала прочитайте актуальный проект и слайд. После вставки перечитайте результат и проверьте положение. Дальнейшие локальные правки выполняются через обычный `update_slide`; сохраняйте IDs и пользовательское форматирование. Пересоздание элемента из defaults может потерять такие правки.

## Экспорт и проверка

Положение и размер сохраняются в HTML. PDF использует браузерное отображение. Текст окна, терминала и стикера расположен вне SVG и может быть перенесён в отдельные редактируемые текстовые элементы PPTX. То, станут ли SVG-контуры фигурами или изображением, зависит от поддержки конкретного элемента экспортёром. Не считайте растровую картинку редактируемым вектором. Проверяйте итоговую геометрию и возможность редактирования в PowerPoint отдельно.

При добавлении нового элемента проверьте безопасные значения, отсутствие внешних ресурсов и столкновений SVG IDs, читаемость текста, движение и изменение размера группы. Обычный текст должен оставаться HTML-текстом. Сложный эффект не требует нового формата сцены или отдельного фреймворка.
