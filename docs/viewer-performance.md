# Переключение слайдов без лишнего перестроения

Просмотрщик сохраняет исходные узлы слайдов. При переходе меняются только предыдущий и следующий слайды; переход на уже выбранный слайд ничего не перестраивает и не обрывает текущую анимацию. Первый слайд показывается сразу: поздняя загрузка модуля эффектов не запускает повторное появление поверх уже показанного кадра.

Во время эффекта предыдущий слайд временно остаётся под входящим, затем его стили восстанавливаются. Его HTML не копируется. В растворении предыдущий слой остаётся непрозрачным: одновременное исчезновение обоих слоёв давало тёмный провал между кадрами. Быстрое листание отменяет текущий переход и освобождает временное состояние; пользовательский HTML не меняется.

Обзор создаётся при первом открытии. Заголовки доступны сразу, а миниатюры получают HTML по мере приближения к видимой области обзора. Окно выбора эффектов повторно использует документ предпросмотра, если HTML/CSS не изменились; новые правки создают новый предпросмотр. Закрытое окно не запускает запоздавшую анимацию после загрузки.

## Редактор и загрузка сайта

Редактор сохраняет документ iframe при листании, правках текста и свойств темы. Обновляются HTML слайда и нужные стили. Миниатюры имеют стабильные узлы; видимые и соседние миниатюры обновляются пакетно, остальные загружаются при прокрутке. Перетаскивание объединяет события указателя в один кадр и применяет окончательную позицию при отпускании.

Карточки проектов и тем сохраняют предпросмотр при поиске. Обложки проектов читаются по мере приближения к экрану. Холст темы объединяет быстрые изменения свойств; сохранённое выделение не переключает выбранную панель редактора.

JS/CSS приложения используют приватный ETag и проверку актуальности: повторная загрузка неизменённого файла получает 304, обновлённый код — новый ответ. Версионные файлы подсветки/форматирования кешируются как immutable. HTML, API, пользовательские изображения, чаты и данные презентаций сохраняют `no-store`; проверка авторизации выполняется до условного ответа.

Дополнительные проверки: `editor-performance-ui.js`, `gallery-performance-ui.js` и `static-cache.test.js`. На временной презентации из 22 слайдов начальных присваиваний `srcdoc` стало 12 вместо 23. Листание и ввод текста не перезагружали холст; 300 событий перемещения дали одно обновление в проверяемом кадре. Это измерение работы DOM в тесте, а не гарантия времени кадра на любом устройстве.

## Проверка

`test/viewer-performance-ui.js` создаёт временную презентацию из 60 слайдов по 64 карточки. Он проверяет задержанную загрузку эффектов, отсутствие копирования при 30 быстрых переходах, ограничение числа изменений DOM, отсутствие тёмного провала, отложенные миниатюры, повторное открытие предпросмотра, полноэкранный режим, reduced motion, публичный просмотр без заметок и автономный HTML.

```sh
node test/viewer-performance-ui.js
```

Можно указать `PRESENTATION_BROWSER_PATH`, если Chromium установлен вне стандартного каталога Playwright. Время выполнения не является жёстким порогом теста: оно зависит от машины. Проверяются структурные причины задержек и корректность изображения.

Один локальный замер на такой же синтетической презентации показал:

| Показатель | До | После |
| --- | ---: | ---: |
| Узлы DOM до открытия обзора | 47 565 | 23 745 |
| Предварительные копии слайдов для обзора | 60 | 0 |
| Копии слайдов при 30 переходах | 30 | 0 |
| Изменения атрибутов слайдов при 30 переходах | 1 978 | 474 |
| JavaScript для этих переходов | 54,3 мс | 19,1 мс |

Проверка кадров подтвердила, что поздний импорт больше не переводит видимый первый слайд из непрозрачного в прозрачный. Во время растворения суммарное покрытие двух слоёв оставалось равным 1. Эти цифры относятся к локальной тестовой презентации; они не измеряют сервер, сеть или пользовательское устройство.
