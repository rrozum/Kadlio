# Хранение и конфликты

Данные установки сохраняют прежний формат. Переезд исходников по каталогам не мигрирует презентации, темы, историю или SQLite.

## Коннекторы и репозитории

`backend/storage/connectors/sqlite.js` открывает Node SQLite с существующей схемой. `backend/storage/repositories/auth.js` содержит SQL пользователей и сессий. Auth-сервис проверяет пароль, выдаёт cookie и отзывает сессии через этот репозиторий.

При запуске пустой установки Auth-сервис создаёт первого владельца из `ADMIN_USERNAME`/`ADMIN_PASSWORD`. Репозиторий проверяет отсутствие пользователей и вставляет запись одним SQL-запросом: параллельный запуск не перезаписывает уже созданный аккаунт. В SQLite хранится хеш пароля с солью; повторный запуск не меняет пароль и сессии.

`backend/storage/connectors/json-files.js` отвечает за JSON и атомарную запись файлов. `PresentationRepository` владеет JSON-метаданными, чтением snapshot и очередью изменений; `ThemeRepository` — записями темы и её ресурсами. Многофайловые изменения HTML слайдов, CSS и assets координирует `engine/presentations/service.js`, сохраняя существующие fs-операции и порядок записи. Это разделение ответственности, а не полная замена любого файлового I/O универсальным репозиторием.

Собственные репозитории ИИ находятся рядом с модулем в `backend/modules/ai/repositories/`. Это модульное состояние — настройки, история и workspaces — а не таблицы внутри движка презентаций.

Если нужно другое хранилище, меняйте реализацию репозитория с сохранением его observable-контракта: not found, текущие версии, CAS, атомарная публикация и приватность. Один новый SQL-запрос должен оставаться в соответствующем репозитории, а не в HTTP-маршруте.

## Приватный каталог

```text
PROJECTS_DATA_DIR/
  auth.sqlite                пользователи и сессии, если AUTH_DB не переопределён
  agent-token                токен внутреннего MCP bridge
  projects/<id>/
    presentation.json        метаданные, версии, порядок и timeline
    slides/*.html            исходники слайдов
    theme.css                CSS презентации
    assets/                  собственные изображения и видео
    materials/               исходные материалы
    feedback.json            ещё не одобренные гостевые отзывы
  themes/<id>/               библиотечные темы и их assets
  elements/<id>/             пользовательские дизайнерские элементы
  effect-snippets/            исходники переиспользуемых JS-эффектов
  ai/
    settings.json            настройки провайдера, включая серверный ключ
    chats/                   история чата проекта и themes/
    attachments/             приватные вложения
    workspaces/              изолированное состояние ACP
    document-previews/       приватный кэш изображений документов
```

Точная раскладка внутренних файлов конкретного модуля задаётся его репозиторием. `AUTH_DB` может лежать отдельно; тогда его необходимо отдельно включать в резервную копию.

Не коммитьте этот каталог. Авторизация Codex, производные auth.json, history, token и backups остаются приватными и после переноса в Docker.

## CAS и очереди

Редактор, агент и второе окно могут начать правку одной версии. Клиент читает её, передаёт версию вместе с изменением и получает конфликт, если другой писатель уже сохранил обновление. Нельзя скрывать конфликт повтором со «свежей» версией без прочтения и слияния намерения.

Стабильный project/slide/block ID связывает исходник с аннотациями, заметками, контекстом чата и runtime. Перестановка слайдов меняет порядок и вычисленные номера, а не идентичность объектов.

Очереди сериализуют запись в пределах проекта/тематического ресурса и модуля. При операции, затрагивающей несколько хранилищ, сохраняйте существующий порядок захвата, например project → materials. Атомарный rename файла не является распределённой транзакцией сразу по всем файлам: не обещайте такую гарантию новому адаптеру без реализации.

## Снимки оформления и дополнений

Применение темы копирует снимок и связанные ресурсы в проект. Правка/удаление библиотечного исходника не переписывает существующие слайды.

Применённые JS-эффекты и дизайнерские элементы тоже сохраняют самостоятельное содержимое. Transient CSS, анимированные позиции и runtime iframe не входят в сохранение холста.

Pending feedback хранится вне презентационного snapshot и инструментов агента. Только явное действие авторизованного владельца создаёт обычную аннотацию и чат-запись; запуск модели выполняется отдельно.

## Резервное копирование

Перед миграцией сохраните весь приватный каталог и отдельный AUTH_DB, если он находится снаружи. Для простой файловой копии остановите сервис; иначе несколько JSON/HTML и SQLite могут отражать разные моменты.

Обычная публикация кода не удаляет данные, пользователей, сессии и историю. Проверки запускайте на временной установке; восстановление backup проверяйте в отдельном каталоге/volume.
